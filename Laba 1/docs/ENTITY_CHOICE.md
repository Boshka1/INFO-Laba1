# Лабораторная работа №1. Пункт 2: Выбор независимой сущности

## Вариант 7. Нотариальная контора

### 1. Анализ сущностей предметной области

В спроектированной ER-модели присутствуют три сущности:
1. **`contracts` (Документы / Сделки)** — **зависимая сущность** (транзакционная таблица связей). Запись об оказанной услуге не может существовать без клиента (`client_id`) и услуги (`service_id`).
2. **`services` (Нотариальные услуги)** — **независимая сущность-справочник**. Содержит 4 атрибута:
   * `id`
   * `name` (наименование услуги)
   * `description` (описание регламента)
   * `base_rate` (базовый тариф)
3. **`clients` (Клиенты нотариальной конторы)** — **независимая стержневая сущность**. Существует автономно в системе и содержит 8 атрибутов:
   * `id` (уникальный идентификатор)
   * `name` (наименование организации / ФИО гражданина)
   * `activity_type` (вид деятельности)
   * `phone` (контактный номер телефона)
   * `address` (юридический / фактический адрес)
   * `inn` (идентификационный номер налогоплательщика — ИНН)
   * `email` (адрес электронной почты)
   * `contact_person` (ФИО контактного лица / представителя)

---

### 2. Обоснование выбора

Для дальнейшей работы над лабораторными работами **ЛР1 – ЛР4** выбрана сущность **`Client` (Клиент)** по следующим причинам:

1. **Критерий независимости:** Сущность не имеет внешних ключей (`foreign keys`) и существует независимо от факта совершения сделок.
2. **Максимальное число полей:** Содержит 8 полей (против 4 у `services`), что полностью удовлетворяет условию *«выбрать независимую сущность с наибольшим числом полей»*.
3. **Разнообразие форматов данных:** Поля сущности `Client` включают числовые идентификаторы, текстовые поля и форматированные строки (телефон, email, ИНН), что позволяет полноценно реализовать и продемонстрировать механизмы валидации, инкапсуляции и парсинга (строки, JSON).
4. **Прямое соответствие заданию:** В пункте 8 ТЗ в качестве примера краткой версии сущности прямо приводится структура: *«Фамилия Инициалы, только один контакт, без адреса, без контактных лиц»*, что дословно соответствует модели `Client` (краткая версия: `id`, `name`, `activity_type`, `phone`).
